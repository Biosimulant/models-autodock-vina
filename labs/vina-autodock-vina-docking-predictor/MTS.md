# Vina research-Lab repair specification

The Lab executes one official AutoDock Vina 1.2.7 command for a prepared receptor–ligand PDBQT pair and a declared search box. It parses Vina's output, preserves its pose ordering, splits pose files, and merges the top pose with the receptor for inspection. This is a thin docking wrapper; no scoring equations or fabricated binding measurements are introduced.

Two `ONCE_BEFORE_RUN` modules form the graph: docking and presentation. Typed record envelopes carry the existing four outputs. The visualization has no terminal numerical outputs; `pose_summary`, `docking_summary`, `structure_artifacts` and `run_metadata` are the results of record. Runtime dependencies are pinned to Biosimulant 0.0.34; Vina binaries are selected by upstream version and platform. The runtime has CPU requirements. Legacy duration and sampling settings do not affect finite invocation counts.

Run options merge with immutable constructor defaults on each override. Unknown keys, non-object options, nonfinite values, booleans supplied as numbers, nonpositive box sizes and invalid integer ranges are rejected before a docking command launches. Paths must resolve to existing files. Actual input bytes are hashed before the command. Validation or command failures expose an error rather than ranked success output; malformed options may fail at the typed input boundary. A CLI nonzero exit does not become a successful docking result.

Default example: packaged 1iep files, center [15.19, 53.903, 16.917] Å, size [20,20,20] Å, exhaustiveness 32, maximum 9 poses, energy range 3 kcal/mol, CPU count 2, seed 2026, scoring vina. The geometry and prepared source bytes are unchanged. The seed and CPU count make the run settings explicit. A different seed is a sampling experiment, not a new biological measurement.

Acceptance requires actual command completion with nonempty finite ranked poses, a readable merged structure, recorded input checksums and seed, and intact output paths. Repeat the same seeded run on the same binary and host to evaluate reproducibility. Unit checks cover option merging, invalid settings, truthful score labels and preservation of provenance on failure; fake command fixtures test plumbing only. Compare the wrapper's reported poses with the generated native PDBQT annotations. No universal score threshold or crystal RMSD claim is imposed without an independently justified target-specific criterion.

Limitations: rigid receptor, prepared inputs only, no AutoDock4 affinity-map interface, no receptor/ligand preparation, no experimental affinity or clinical prediction. Lower docking scores and within-run RMSD bounds are presented with these limits in the result itself. Formal scientific qualification and a managed-run Passport remain separate from local execution checks.
